AA+ level of accessibility

Accessibility is the inclusive practice of ensuring that there are no barriers to prevent interaction with, or access to, websites (and other digital properties) for those with disabilities.

This can include those with visual, hearing, motor, and cognitive disabilities or impairments. These individuals need to utilize a range of tools and technologies to help overcome obstacles and properly interact with digital content.

For example, those with visual impairments may use screen readers, zoom functions, or rely on high contrast content. Individuals who are deaf or hard of hearing, will require captions and transcripts to engage with multimedia content. We must make certain that our digital applications and properties can be explored solely with the use of keyboard interactions to accommodate those with motor function impairments. Users with cognitive disabilities rely on consistency and logic to properly navigate and utilize digital content. Therefore, we will always work to leverage industry standards for user interfaces and common best practices for user experience – such as placing web elements where users would expect to find them and using common naming conventions and taxonomies.

Accessibility is built on 4 key principles – referred to as POUR.

Perceivable

Information and the user interface must be presented to users in ways they can perceive. Providing text alternatives for non-text content (such as alt-text for important imagery), using captions, and generally making it easier for users to see and hear our content.

Operable

UI components and navigation must be operable. Can someone navigate our content with only a keyboard? Do we give them enough time to engage with or read content on interactive websites? Are we helping users to navigate and find content easily? All questions we should be asking as we plan and develop.

Understandable

Information and the operation of the user interface must be understandable. Content should not just be readable, but we should be using common naming conventions that will help users avoid mistakes. Our digital content should generally appear and operate in predictable ways.

Complying with accessibility standards is about being a good corporate citizen. We harm both ourselves and our users when we create content with potential barriers. Accessibility is also legally mandated in several countries around the world – with varying laws and regulations supporting this effort.

Robust

Content must be robust enough that it can be interpreted reliably by a wide variety of user agents, including assistive technologies. This means that users must be able to access the content as technologies advance (as technologies and user agents evolve, the content should remain accessible).

To reinforce Deloitte’s business and brand strategy, Deloitte adheres, without exception, to the web content accessibility guidelines AA standard.

The power of the web is in its universality – access by everyone regardless of disability is an essential aspect, (Tim Berners-lee, W3C Director and inventor of the World Wide Web).

For more information on WCAG standards please visit W3C or reach out to mailto:GlobalBrandingTeam@deloitte.

Color themes & sizes

3 color themes - accessible green, accessible blue, high contrast black.

All three are brand compliant. Any can be selected as core for any project.

Mixing themes based on accessible colors is forbidden. Components from high contrast theme can be used as complimentary to any accessible theme.

3 sizes for components - large (x10), medium (x8), small (x6).

Main purpose of different sizes for elements - to support different data density.

We recommend to utilize components from one size groups for core elements ex: actions, navigation elements, grids, content grouping.
