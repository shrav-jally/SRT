Page Finder Agent
table_finder.py — ★ LLM-first page identification with deterministic validation. Identifies BS, P&L, CF, Notes pages + statement type
→ ★ Quick deterministic check (cost optimization, ~70% skip LLM)
→ ★ find_pages_by_llm() — PRIMARY page identification
→ ★ LLM detects statement_type (Standalone/Consolidated) in same call
→ _validate_with_deterministic() — SECONDARY validation
→ Union merge: LLM pages ∪ deterministic pages (no loss)
→ Continuation page expansion (up to 4 pages ahead)
→ Cross-validate statement type (LLM vs keyword scan)
→ Notes page detection (always deterministic, broad search)
→ Deterministic-only fallback when LLM unavailable
→ detection_method: llm_primary | llm_primary_validated | quick_deterministic | deterministic_fallback
Why
LLM understands page context semantically — it can identify a Balance Sheet even with non-standard titles, CID-fragmented text, or bilingual headers. Deterministic title scanning misses these cases. LLM-first ensures highest accuracy; deterministic validation catches any LLM hallucinations.
How
3-step LLM-first cascade: (1) _quick_deterministic_check() — if standard Schedule III titles find all 3 statements with confidence ≥ 1.0, skip LLM (cost savings ~70%), (2) find_pages_by_llm() — sends page snippets to LLM with optional deterministic hints, gets page numbers + statement_type, (3) _validate_with_deterministic() — runs full deterministic scan, merges pages (union), expands continuations, cross-validates statement type.
Standard
Schedule III mandates specific titles: "Balance Sheet as at March 31", "Statement of Profit and Loss for the year ended". These enable the quick deterministic check to skip LLM for standard PDFs. Non-standard PDFs (merged reports, bilingual) require LLM's semantic understanding.
🧠
★ LLM PRIMARY — find_pages_by_llm(): Sends text snippets from sampled pages to the LLM with an optional hint from the quick deterministic check. The LLM returns page numbers for BS/P&L/CF/CoE AND the statement_type (Standalone/Consolidated) in a single call — no extra cost. Results are then validated by _validate_with_deterministic() which runs a full deterministic scan and merges pages (union). Always enabled when LLM is available, unless quick deterministic check finds all 3 statements with standard titles.

Extractor Agent
text_table_extractor.py — Converts PDF text into structured row data using deterministic line-by-line parsing
→ Extract text lines from each PDF page
→ Find statement start (skip auditor's report)
→ Parse each line: label + note_ref + values
→ Detect indent level (leading spaces, (i)/(A) prefixes)
→ Track section headers (ASSETS, LIABILITIES, etc.)
→ Merge fragmented rows (label-only + values-only)
→ Split inline section headers
→ Detect unit (₹ in Lakhs/Crores/Millions)
→ Deduplicate across pages
→ Return ExtractedTable with rows + year_headers + unit
Why
Indian AR PDFs have no visible table borders (gridless). pdfplumber.extract_tables() fails. But extract_text() produces well-structured lines with labels on the left and numbers on the right — perfect for regex parsing.
How
Right-to-left token scan separates values from labels. Note references (small integers 1-3 digits) distinguished from financial values (have commas/decimals). CID font placeholders stripped via regex. Fragmented rows merged (label-only + values-only lines).
Standard
Ind AS 1 prescribes line-item presentation format: (a), (b), (i), (ii) sub-item numbering. The Extractor detects these prefixes to set indent_level, which the Mapper uses for section-aware matching.

statement_type, rows: list[ExtractedRow] (label, note_ref, values, indent_level, is_section_header, is_total), year_headers, unit
Orchestrator internal: _convert_extracted_table_to_tabular()
Bridges Extractor → Mapper format. Adds "Section" column from section tracking. Headers: Label | Section | Note | Current Year | Previous Year
table_headers: list[str], table_rows: list[list[str]], target_year: int

Mapper Agent
data_mapper.py — Maps extracted row data to Excel template using keyword aliases → ★ LLM (primary) → fuzzy matching (fallback) + 3-way merge
→ Keyword alias pre-pass (30+ BS, 10+ P&L, 50+ Notes aliases)
→ ★ LLM mapping via map_by_llm() — PRIMARY method
→ Fuzzy matching — FALLBACK only (when LLM unavailable/misses)
→ 3-way merge: alias > LLM > fuzzy (_merge_alias_llm_and_fuzzy)
→ Section-aware scoring (+15 same section, −20 cross-section)
→ Year column auto-detection (_detect_year_column)
→ CF structural matching (Net cash rows in order)
→ CF phrase + anchor alias matching (CID-tolerant)
→ Notes → OFI 4-phase mapping (alias → context → ★ LLM → fuzzy)
→ Parent-child dedup across all 3 sources (alias/LLM/fuzzy)
→ Default zeros for commonly absent items
→ Derived items (residual computation)
Why
Fuzzy matching measures character similarity but misses semantic equivalence. "Right of use assets" ≈ "Others (NC assets)" — fuzzy score = 0, but LLM understands the accounting context. LLM also handles abbreviations (CWIP, PPE), CID-fragmented text, and section disambiguation that fuzzy cannot.
How
Three-tier cascade: (1) keyword aliases for deterministic exact matches, (2) map_by_llm() sends unmapped items + PDF rows to LLM, gets JSON mappings with confidence, (3) fuzzy matching as fallback for anything LLM missed. 3-way merge with priority: alias > LLM > fuzzy. Parent-child dedup across all sources.
Standard
Schedule III defines the exact template structure. Items like "(A) total outstanding dues of micro enterprises and small enterprises" are statutory requirements from MSME Act, Section 15. Keyword aliases encode standard names; LLM handles the non-standard variations.
🧠
★ LLM PRIMARY — map_by_llm(): After keyword alias pre-pass, map_by_llm() is called for each statement (BS, P&L, CF, Notes→OFI). It receives unmapped template items (with sections) + all PDF rows (with values and sections), and returns structured JSON mappings. LLM-matched row indices are excluded from the fuzzy fallback pass. Confidence capped at 0.90, method = "llm". Always enabled when LLM is available.
🧠
LLM SECONDARY — Mapping Verification: When verify_with_llm=True, the Orchestrator calls _verify_mappings_with_llm() which checks only mappings with confidence < 0.7. The LLM can mark mappings as CORRECT or WRONG + suggest the correct template item. Runs AFTER primary mapping is complete.

Writer Agent
excel_writer.py — Writes mapped data to Excel template with formulas, raw data sheets, and metadata
→ Write BS values to column C with section-based row finding
→ Write P&L values to column C
→ Write CF + OFI values to column C
→ Apply Excel formulas for computed rows (totals, EBITDA)
→ Apply default zeros for empty cells in known rows
→ Write "Raw BS", "Raw P&L", "Raw CF" sheets (transparency)
→ Write "Meta Data" sheet (extraction stats)
→ Format numbers as #,##0.00
Why
Formulas ensure computed rows (Total Assets, EBITDA, etc.) auto-calculate from their components. This prevents inconsistencies where an extracted total doesn't match the sum of its parts. Raw data sheets provide auditability.
How
Section-based row finding: each MappingResult has a "section" field. The Writer searches within the section's row range first, then falls back to full-column search. Formulas overwrite extracted values in formula rows to prevent double-counting.
Standard
BS formula: Total Assets = NC Assets + Current Assets. P&L formula: EBITDA = PBT + D&A + Finance costs. These follow standard financial analysis definitions used in Indian credit analysis.

🧩 Agentic Patterns Used

🎯 Orchestration Pattern

A single Orchestrator agent coordinates all other agents. It knows the full pipeline but executes no domain logic itself. Each agent is independently testable with clear input/output contracts.

SmartExtractionAgent.run() calls find_financial_statements(), extract_table_from_pages(), map_balance_sheet(), write_all_sheets() — but never parses a PDF line or matches a keyword itself.

🔄 LLM-First with Deterministic Validation

LLM is the PRIMARY method for both page finding and mapping. Deterministic approaches serve as validation/fallback. For page finding: quick deterministic check (cost optimization) → LLM page ID (primary) → deterministic validation. For mapping: keyword aliases → LLM mapping (primary) → fuzzy matching (fallback). This ensures highest accuracy while maintaining cost efficiency.

Page Finder: quick_det_check → ★ find_pages_by_llm() → _validate_with_deterministic(). Mapper: keyword aliases → ★ map_by_llm() → fuzzy matching (fallback). Statement type: LLM-detected with page ID → cross-validated by keyword scan.

🧠 LLM as Primary Mapper, Fuzzy as Fallback

The LLM is the PRIMARY mapping method after keyword aliases. It understands semantic equivalence ("Right of use assets" ≈ "Others"), section context, and abbreviations that fuzzy matching misses. Fuzzy matching is the fallback — only used when LLM is unavailable or returns no results for an item.

BS mapping: alias finds "CWIP" → "(b) Capital work-in-progress". LLM finds "Right of use assets" → "(iv) Others (NC assets)" (fuzzy score would be 0). Fuzzy catches any remaining items LLM missed. 3-way merge: alias > LLM > fuzzy.

📐 Section-Aware Disambiguation

The same label can appear in multiple sections (e.g., "Borrowings" in both NC and Current liabilities). Agents use section context to disambiguate: the Extractor tracks sections, the Mapper uses section-aware scoring, the Writer searches within section row ranges.

Mapper: +15 bonus for same-section match, −20 penalty for cross-section. Writer: searches NC liabilities rows (42-50) before Current liabilities rows (53-59) for NC "Borrowings".

🔀 Smart Merge with Override

When multiple sources provide values for the same template item, the Orchestrator applies intelligent merge logic: Notes values override default_zero items but NOT real extracted values. This ensures the most specific data wins.

CF has "Contingent Liabilities = 0" (default_zero). Notes extraction finds "Contingent Liabilities = 2,315.59" (notes_alias). Smart merge: Notes value wins → 2,315.59. But if CF had a real extracted value, it would be kept.

📊 Progress Reporting

The Orchestrator reports progress at each step via a callback function. This enables real-time UI updates without coupling the agents to the web interface. Agents don't know about HTTP or SSE — they just call the callback.

_report_progress("Extracting Balance Sheet", "active", 0, "Extracting from pages [5, 6]...") → callback → SSE event → browser progress bar update.

🏷️ Two-Pass Optimal Assignment

The Mapper collects ALL candidates before assigning any. This prevents greedy first-come-first-served mismatches. Candidates are sorted by adjusted score (fuzzy + section bonus) and assigned optimally — the best match always wins.

"Borrowings" appears in both NC and Current sections. Without two-pass, the first "Borrowings" might steal the NC template slot. With two-pass, section-aware scoring ensures NC "Borrowings" → NC template, Current "Borrowings" → Current template.

🛡️ Formula Row Protection

Template items that are computed by Excel formulas (totals, subtotals, EBITDA) are NEVER mapped from extracted data. The Mapper skips them, and the Writer overwrites them with formulas. This prevents double-counting.

BS: "(h) Financial Assets" is a formula row = sum of (i)+(ii)+(iii)+(iv). If the Mapper mapped a PDF value here AND to the sub-items, the Writer's SUM formula would double-count. FORMULA_TEMPLATE_ITEMS set prevents this.
